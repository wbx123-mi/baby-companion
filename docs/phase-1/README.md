# Baby Companion 阶段一设计索引

## 目标

阶段一优先让家庭尽快开始记录宝宝出生后的内容，范围限定为：

- 微信 OpenID 登录与应用内部账号映射
- 首位用户创建家庭和宝宝档案
- 图文成长记录
- UniApp 兼容的私有图片表单直传
- 支持补录宝宝出生后的历史日期
- 成长时间线
- 本地草稿与失败重试
- 管理员、父母、亲属的基础权限校验

家庭邀请、里程碑、语音、回收站、数据导出和 AI 不进入本阶段编码范围，但数据库设计会预留扩展位置。

阶段一的真实使用入口只开放首位创建者，角色为 `ADMIN`；`PARENT`、`RELATIVE` 的数据结构和服务端权限规则在本阶段实现并测试，但普通用户加入家庭需要等待阶段二的邀请流程。

## 已确认决策

- 客户端：UniApp 标准版、Vue 3、TypeScript、Pinia、wot-design-uni、UnoCSS
- 服务端：NestJS、TypeScript
- 数据库：MySQL、Prisma
- 身份：`AppID + OpenID` 关联应用内部 `userId`，不强制手机号
- 部署：开发期本地 Docker；后续使用低成本 CloudBase 资源
- 仓库：开发期私有，完成脱敏后再公开
- AI：阶段一不接入

## 阶段一完成定义

只有同时满足以下条件，阶段一才算完成：

1. 新用户能够通过微信身份登录，重复登录不会创建重复账号。
2. 首位用户能够在一个事务内创建家庭、管理员成员关系和宝宝档案。
3. 用户能够创建纯文字、纯图片和图文成长记录。
4. 用户能够补录宝宝出生后任意合法时间的记录。
5. 时间线能够稳定分页，按照实际发生时间倒序展示。
6. 所有查询和写入都经过后端家庭成员权限校验。
7. 图片默认私有，客户端不能获得永久公开地址。
8. 网络失败或小程序重启时文字草稿不丢失，本地配额允许时草稿图片也可以恢复。
9. 重复提交不会生成重复记录，并发初始化不会为同一用户创建两个家庭。
10. Refresh Token 支持轮换和旧令牌复用检测，随机无效 Token 不会误撤销其他会话。
11. 核心权限、数据隔离和接口流程有自动化测试。
